# odoo_account_bank_statement

## Source system
This table originates from Odoo ERP, specifically the accounting module. The naming convention (`account_bank_statement`) and the presence of Odoo-standard audit columns (`create_uid`, `write_uid`, `create_date`, `write_date`) are characteristic of Odoo's PostgreSQL-based backend schema.

## Functional process 
This table supports the bank reconciliation and cash management process within the accounting module. It tracks the header-level information for bank statements imported or manually entered into the system, linking them to specific journals and companies to ensure financial records align with external bank balances.

## Description
One row in this table represents a single bank statement header, capturing the opening and closing balances for a specific date and journal. It serves as a raw landed copy of the Odoo `account.bank.statement` model, providing the foundational data for reconciling bank transactions against ledger entries.

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `company_id` → `res_company.id` (Standard Odoo multi-company architecture).
    - `journal_id` → `account_journal.id` (Links to the specific bank account journal).
    - `create_uid` / `write_uid` → `res_users.id` (Standard Odoo audit trail).
- **Natural keys (inferred):** 
    - `name` (Often acts as the business-facing statement number).

## Caveats for downstream consumers

- **Sensitive Data:** Contains internal user IDs (`create_uid`, `write_uid`) and financial balances; ensure access is restricted to authorized accounting personnel.
- **Timestamps:** `create_date` and `write_date` are stored in the database's local timezone (typically UTC in Odoo deployments); verify against system settings.
- **Data Integrity:** `balance_end` vs `balance_end_real` discrepancy is a key indicator for reconciliation issues; downstream models should flag rows where these values do not match.
- **Soft Deletes:** Odoo typically performs hard deletes on records; assume no soft-delete flag exists unless `active` column is present (not present here).
