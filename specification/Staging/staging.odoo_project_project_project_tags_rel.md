# odoo_project_project_project_tags_rel

## Source system
Odoo ERP. The naming convention `odoo_project_project_project_tags_rel` is characteristic of Odoo's automated many-to-many relationship tables, which are generated by the ORM to link project entities to their associated tag entities.

## Functional process 
Project management and categorization. This table supports the many-to-many relationship between projects and tags, allowing users to classify projects with multiple labels for reporting, filtering, and organizational purposes within the Odoo Project module.

## Description
One row represents a single association between a specific project and a specific tag. This is a junction table used to resolve the many-to-many relationship between the `project_project` and `project_tags` entities in the Odoo database. It serves as a raw landing of the relational link without additional metadata.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| project_project_id | INTEGER | false | Foreign key to the project | References the primary key of the project entity. |
| project_tags_id | INTEGER | false | Foreign key to the tag | References the primary key of the project tag entity. |

## Keys

- **Primary key (inferred):** The composite key (`project_project_id`, `project_tags_id`).
- **Foreign keys (inferred):** 
    - `project_project_id` → `project_project.id`: Links to the project definition.
    - `project_tags_id` → `project_tags.id`: Links to the tag definition.
- **Natural keys (inferred):** Not confidently inferable.

## Caveats for downstream consumers

- This table contains no surrogate primary key; use the composite of both columns for unique identification.
- There is no audit or timestamp information (e.g., `created_at`) available in this junction table.
- As a standard Odoo relational table, it does not support soft deletes; if a relationship is removed in the source UI, the row is typically deleted from this table.
- Ensure joins to parent tables handle the `INTEGER` type consistently to avoid implicit casting overhead.
