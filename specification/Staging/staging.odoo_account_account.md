# odoo_account_account

## Source system
Odoo ERP (specifically the financial/accounting module). The table structure, column naming patterns (`create_uid`, `write_uid`, `create_date`, `write_date`), and accounting fields (`account_type`, `code_store`, `reconcile`, `deprecated`) are characteristic of the standard Odoo ORM underlying the `account.account` model.

## Functional process
General Ledger and Chart of Accounts management within the Record-to-Report (R2R) accounting process. This table defines the master chart of accounts used to categorize financial transactions, track assets, liabilities, equity, revenues, and expenses, and enforce reconciliation rules across journal entries.

## Description
Each row represents a single general ledger account within the chart of accounts. The grain is one row per GL account definition. In this staging layer, it serves as a raw landed structural replica of Odoo's `account.account` model to be transformed downstream into standard financial dimensions.

## Columns

## Keys

- **Primary key (inferred):** `id` (source sequence-backed primary key).
- **Foreign keys (inferred):**
  - `currency_id` → `res_currency.id` (standard Odoo currency definition table).
  - `create_uid` → `res_users.id` (audit tracking for the user who created the account).
  - `write_uid` → `res_users.id` (audit tracking for the user who last updated the account).
- **Natural keys (inferred):**
  - `code_store` (or the parsed account code extracted from JSONB per company/locale context).

## Caveats for downstream consumers

- Timestamps (`create_date`, `write_date`) are stored without explicit timezone offsets (`TIMESTAMP`), but standard Odoo installations record all system audit timestamps in UTC.
- Account names (`name`) and codes (`code_store`) are stored as `JSONB` key-value pairs to support localization and multi-company setups; query writers will need to parse JSON keys (e.g., `name->>'en_US'`) to extract display strings.
- Deprecated or retired accounts remain in this table with `deprecated = true` rather than being physically deleted; query writers building active Chart of Accounts reports should filter `WHERE deprecated IS NOT TRUE`.
- The table contains internal configuration and audit metadata; no sensitive personal data (PII) or secrets are present, though internal financial structures may be confidential.
