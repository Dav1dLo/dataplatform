# odoo_ir_ui_view_custom

## Source system
This table originates from Odoo ERP, specifically the `ir.ui.view.custom` model. The naming convention (`ir_ui_view_custom`) and the presence of Odoo-standard audit columns (`create_uid`, `write_uid`, `create_date`, `write_date`) are characteristic of the Odoo framework's internal metadata layer.

## Functional process 
This table supports the UI customization process within Odoo, allowing users to store personalized modifications to existing views. It tracks which user applied a custom XML architecture (`arch`) to a specific base view (`ref_id`), enabling the system to render user-specific interface overrides.

## Description
One row represents a single custom UI view definition created by a specific user for a base view. This is a raw landed copy of the Odoo system table, serving as the staging point for tracking interface customizations. The grain is one row per user-specific view customization.

## Caveats for downstream consumers

- **Sensitive Data:** The `arch` column may contain UI logic or references that could expose internal system structures; ensure access is restricted.
- **Timezones:** Timestamps (`create_date`, `write_date`) are stored in the Odoo server's local time; verify the server configuration to convert to UTC.
- **Data Integrity:** This is a raw staging table; it may contain orphaned records if the corresponding `ir_ui_view` or `res_users` records have been purged.
- **Soft Deletes:** Odoo typically performs hard deletes on `ir_ui_view_custom` records; assume no soft-delete flag exists unless explicitly added by the ingestion pipeline.
