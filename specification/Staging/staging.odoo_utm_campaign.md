# odoo_utm_campaign

## Source system
This table originates from Odoo ERP, an open-source business management suite. The naming convention (`utm_campaign`, `create_uid`, `write_uid`, `company_id`) and the presence of `JSONB` fields for localized titles are characteristic of Odoo's PostgreSQL-based backend schema.

## Functional process 
This table supports the marketing automation and lead tracking process within the Odoo CRM/Marketing modules. It acts as the central repository for defining UTM (Urchin Tracking Module) campaigns, which are used to track the performance of marketing initiatives across various channels and sources.

## Description
One row in this table represents a single marketing campaign definition used to track inbound traffic or lead sources. This is a raw landing table in the Staging layer, containing the direct, un-transformed state of the campaign records as they exist in the Odoo operational database.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Sequence-generated by Odoo. |
| user_id | INTEGER | false | Owner user ID | References the internal user responsible for the campaign. |
| stage_id | INTEGER | false | Campaign stage ID | References the current status or pipeline stage of the campaign. |
| color | INTEGER | true | UI color index | Used for visual representation in the Odoo dashboard. |
| create_uid | INTEGER | true | Creator user ID | ID of the user who created the record. |
| write_uid | INTEGER | true | Last modifier user ID | ID of the user who last updated the record. |
| name | VARCHAR | false | Campaign name | The internal identifier or name of the campaign. |
| title | JSONB | false | Localized campaign title | Multi-language title storage; requires parsing for specific locales. |
| active | BOOLEAN | true | Soft-delete flag | If false, the campaign is hidden from active views. |
| is_auto_campaign | BOOLEAN | true | Automation flag | Indicates if the campaign is managed by an automated workflow. |
| create_date | TIMESTAMP | true | Creation timestamp | Recorded in UTC by the Odoo application layer. |
| write_date | TIMESTAMP | true | Last update timestamp | Recorded in UTC by the Odoo application layer. |
| company_id | INTEGER | true | Company ID | Multi-company context identifier. |

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `user_id` → `res_users.id` (Standard Odoo pattern for record ownership).
    - `company_id` → `res_company.id` (Standard Odoo pattern for multi-company isolation).
    - `create_uid` / `write_uid` → `res_users.id` (Audit trail references).
- **Natural keys (inferred):** 
    - `name` (While not strictly enforced as unique in all Odoo versions, it serves as the business-level identifier for campaigns).

## Caveats for downstream consumers

- **PII/Sensitivity:** Contains user IDs (`create_uid`, `write_uid`) which link to internal employee data.
- **Timestamps:** All `TIMESTAMP` fields are stored in UTC.
- **Soft Deletes:** The `active` column acts as a soft-delete flag; ensure queries filter by `active = TRUE` unless historical analysis of deleted campaigns is required.
- **JSONB:** The `title` column contains structured data; use PostgreSQL `->>` or `->` operators to extract specific language keys.
- **Data Integrity:** As a staging table, this may contain duplicates or incomplete records if the Odoo sync process is interrupted.
