# odoo_portal_wizard_res_partner_rel

## Source system
This table originates from Odoo ERP. The naming convention `_rel` combined with the specific entity names `portal_wizard` and `res_partner` is characteristic of Odoo's internal many-to-many relationship tables, which are automatically generated by the ORM to link portal wizard sessions to specific partner records.

## Functional process 
This table supports the "Portal Access Management" process. It tracks which partners (contacts/users) are associated with a specific portal wizard instance, which is used to grant or revoke access to the Odoo customer portal for those partners.

## Description
One row in this table represents a single association between a portal wizard session and a partner record. It serves as a raw landing copy of the many-to-many join table from the Odoo database, facilitating the mapping of partners to their respective portal access invitations.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| portal_wizard_id | INTEGER | false | Foreign key to the portal wizard session | Links to the primary portal wizard record. |
| res_partner_id | INTEGER | false | Foreign key to the partner record | Links to the `res_partner` table. |

## Caveats for downstream consumers

- This table contains no PII directly, but it links partners to portal sessions; ensure access controls are aligned with the `res_partner` table.
- As a raw staging table, it does not contain audit timestamps (e.g., `create_date` or `write_date`) unless they were omitted from the source metadata.
- This is a join table; expect no non-key attributes.
- Queries should assume that the relationship is immutable once created, though Odoo may delete rows if the wizard session is cleared.
