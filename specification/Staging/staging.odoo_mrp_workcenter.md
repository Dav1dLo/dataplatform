# odoo_mrp_workcenter

## Source system
This table originates from Odoo ERP, specifically the Manufacturing (MRP) module. The naming convention (`mrp_workcenter`), the presence of Odoo-standard audit columns (`create_uid`, `write_uid`, `create_date`, `write_date`), and the specific Odoo-style fields like `resource_calendar_id` and `analytic_distribution` confirm this as a direct extraction from an Odoo PostgreSQL database.

## Functional process 
This table supports the Manufacturing Execution System (MES) and production planning processes. It defines the physical or logical work centers where manufacturing operations occur, tracking their capacity, efficiency, hourly costs, and availability for scheduling purposes within the production pipeline.

## Description
One row represents a single manufacturing work center, which is a resource (machine or human station) capable of performing production tasks. This table serves as a raw landed copy of the Odoo `mrp.workcenter` model, providing the foundational configuration for shop floor scheduling and cost accounting.

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):**
    - `resource_id` → `resource_resource.id` (Standard Odoo pattern linking work centers to base resources).
    - `company_id` → `res_company.id` (Standard Odoo multi-company link).
    - `resource_calendar_id` → `resource_calendar.id` (Links to the shift schedule definition).
    - `create_uid` / `write_uid` → `res_users.id` (Links to the system users who performed the actions).
    - `expense_account_id` → `account_account.id` (Links to the General Ledger chart of accounts).
- **Natural keys (inferred):**
    - `code` (Often used as a unique business identifier for work centers in manufacturing environments).

## Caveats for downstream consumers

- **Soft Deletes:** The `active` column acts as a soft-delete flag. Queries should generally filter by `WHERE active = TRUE` unless historical analysis of archived work centers is required.
- **Timestamps:** Odoo stores all timestamps in UTC.
- **Precision:** `DOUBLE PRECISION` fields are used for rates and times; ensure rounding is applied if calculating total costs to avoid floating-point arithmetic issues.
- **PII/Sensitive Data:** While this table contains operational data, `analytic_distribution` may contain references to internal cost centers or project codes that should be handled according to internal data governance policies.
