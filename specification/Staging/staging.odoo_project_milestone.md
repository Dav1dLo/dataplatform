# odoo_project_milestone

## Source system
This table originates from Odoo ERP, specifically the Project Management module. The naming convention (e.g., `create_uid`, `write_uid`, `write_date`) and the presence of project-related fields are characteristic of Odoo's standard ORM-based database schema.

## Functional process 
This table supports the project delivery and billing process, specifically tracking milestones linked to project tasks or sales orders. It is used to monitor project progress against deadlines and to trigger downstream billing events when milestones are marked as reached.

## Description
One row represents a single project milestone defined within an Odoo project. The grain is one row per milestone per project. This table serves as a raw landed copy of the Odoo `project.milestone` model, providing the base data for project tracking and revenue recognition reporting.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Sequence-generated by Odoo. |
| project_id | INTEGER | false | Foreign key to the project | Links to the parent project. |
| create_uid | INTEGER | true | User ID who created the record | References the `res.users` table. |

| deadline | DATE | true | Target completion date | Expected date for milestone achievement. |

| create_date | TIMESTAMP | true | Record creation timestamp | UTC timestamp of ingestion. |
| write_date | TIMESTAMP | true | Last update timestamp | UTC timestamp of last modification. |
| sale_line_id | INTEGER | true | Related sales order line | Links milestone to billing/revenue. |
| quantity_percentage | DOUBLE PRECISION | true | Progress percentage | Represents the portion of work completed. |

## Caveats for downstream consumers

- **Sensitive Data:** Contains user IDs (`create_uid`, `write_uid`) which may map to employee names in other tables.
- **Timestamps:** `create_date` and `write_date` are stored in UTC as per standard Odoo behavior.
- **Soft Deletes:** Odoo typically uses hard deletes for this model; if a record is missing, it has likely been purged from the source.
- **Data Quality:** `quantity_percentage` may contain nulls for milestones that are not yet quantified or are purely descriptive.
