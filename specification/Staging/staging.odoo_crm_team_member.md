# odoo_crm_team_member

## Source system
This table originates from Odoo ERP, specifically the CRM module. The naming convention (`crm_team_member`), the presence of Odoo-standard audit columns (`create_uid`, `write_uid`, `create_date`, `write_date`), and the sequence-based primary key are characteristic of Odoo's PostgreSQL-backed database schema.

## Functional process 
This table supports the CRM lead assignment and team management process. It defines the relationship between specific system users and CRM teams, while also storing configuration parameters for automated lead distribution, such as maximum assignment limits and opt-out preferences for individual team members.

## Description
One row in this table represents a single membership association between a user and a CRM team within the Odoo environment. This is a raw landing table in the Staging layer, capturing the state of team member configurations as they exist in the source system.

## Caveats for downstream consumers

- **Timestamps:** `create_date` and `write_date` are stored in the Odoo server's local time; verify the server timezone configuration before performing time-series analysis.
- **Soft Deletes:** The `active` column acts as a soft-delete flag. Queries should generally filter by `WHERE active = TRUE` unless historical audit is required.
- **Data Sensitivity:** `user_id` and `create_uid`/`write_uid` link to internal system users; ensure these are handled according to internal access control policies.
- **Assignment Domain:** The `assignment_domain` column contains Odoo-specific domain syntax (a list of tuples in string format); this will require parsing if used for logic in downstream layers.
