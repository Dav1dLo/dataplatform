# odoo_pos_session

## Source system
This table originates from Odoo ERP, specifically the Point of Sale (POS) module. The naming convention (e.g., `config_id`, `move_id`, `create_uid`) and the specific functional columns related to cash registers and session states are characteristic of the Odoo `pos.session` model.

## Functional process 
This table supports the retail operations and financial reconciliation process within the Point of Sale module. It tracks the lifecycle of a POS session, from opening the register with an initial cash balance to closing it, reconciling transactions, and finalizing the session for accounting integration.

## Description
One row in this table represents a single POS session, capturing the duration, responsible user, and financial state of a cash register. It serves as a raw landed copy of the Odoo `pos.session` model, providing the audit trail for session-based financial activities in the staging layer.

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `config_id` → `pos_config.id` (Standard Odoo relationship for POS settings)
    - `user_id` → `res_users.id` (Standard Odoo relationship for system users)
    - `cash_journal_id` → `account_journal.id` (Links to accounting journal configuration)
    - `move_id` → `account_move.id` (Links to the resulting accounting journal entry)
    - `employee_id` → `hr_employee.id` (Links to the employee record)
- **Natural keys (inferred):** 
    - `name` (The session name is typically unique within an Odoo installation)

## Caveats for downstream consumers

- **Timestamps:** Timestamps are stored in UTC as per standard Odoo behavior; verify local timezone offsets if reporting on business hours.
- **Sensitive Data:** `access_token` should be excluded from general reporting to prevent unauthorized session access.
- **Soft Deletes:** Odoo typically uses hard deletes for session records; however, verify if the source system has been configured for archival.
- **Precision:** `NUMERIC` types for balances do not specify scale/precision in the metadata; assume standard currency precision (e.g., 18,2) but validate against source DDL.
