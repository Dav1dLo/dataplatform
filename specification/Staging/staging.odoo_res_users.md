# odoo_res_users

## Source system
This table originates from Odoo ERP, specifically the `res_users` model. The naming convention (e.g., `res_users`, `partner_id`, `create_uid`) and the presence of Odoo-specific fields like `odoobot_state` and `property_warehouse_id` are characteristic of the Odoo framework's core user management module.

## Functional process 
This table supports the Identity and Access Management (IAM) process within the Odoo ecosystem. It manages user authentication, system access rights, and user-specific configurations such as sales targets, notification preferences, and portal/website access settings.

## Description
One row in this table represents a single user account registered within the Odoo instance. This is a raw landed copy of the `res_users` table from the source database, serving as the primary source for user-related dimensions and security mapping in the staging layer.

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `partner_id` → `res_partner.id` (Standard Odoo link between user and contact).
    - `company_id` → `res_company.id` (Standard Odoo link for multi-company access).
    - `sale_team_id` → `crm_team.id` (Links user to a specific sales team).
- **Natural keys (inferred):** 
    - `login` (Unique identifier for authentication).

## Caveats for downstream consumers

- **Sensitive Data:** The `password` and `totp_secret` columns contain sensitive security credentials and must be masked or excluded from non-administrative reporting.
- **Timestamps:** All `create_date` and `write_date` values are assumed to be in UTC, consistent with standard Odoo database configurations.
- **Soft Deletes:** The `active` column acts as a soft-delete flag; ensure queries filter by `active = true` unless historical user analysis is required.
- **JSONB:** The `property_warehouse_id` column contains nested data; use PostgreSQL JSONB operators (e.g., `->>`) to extract specific values.
