# odoo_mail_message_reaction

## Source system
This table originates from Odoo, an open-source ERP and CRM platform. The naming convention `mail_message_reaction` and the presence of `message_id`, `partner_id`, and `guest_id` are characteristic of Odoo's internal messaging and chatter system, which tracks user interactions with records.

## Functional process 
This table supports the social and collaboration features within Odoo, specifically tracking emoji reactions or similar feedback markers applied to messages within the system's communication threads. It links specific message instances to the users (partners) or anonymous visitors (guests) who reacted to them.

## Description
One row represents a single reaction instance applied to a specific message by either a registered partner or an anonymous guest. This table serves as a raw landing copy of the Odoo `mail.message.reaction` model, capturing the state of user interactions within the communication module.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Sequence-generated by Odoo. |
| message_id | INTEGER | false | Foreign key to the parent message | Links to the `mail.message` table. |
| partner_id | INTEGER | true | Foreign key to the reacting partner | Represents a registered system user. |
| guest_id | INTEGER | true | Foreign key to the reacting guest | Represents an anonymous or external visitor. |
| content | VARCHAR | false | The reaction content | Typically an emoji character or reaction code. |

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):**

    - `partner_id` → `res_partner.id`: This column identifies the registered user who performed the action.
    - `guest_id` → `mail_guest.id`: This column identifies the anonymous visitor who performed the action.

## Caveats for downstream consumers

- **PII/Sensitive Data:** The `partner_id` and `guest_id` columns link to identity data; ensure appropriate access controls are applied when joining to user profile tables.
- **Data Integrity:** A row will typically have either a `partner_id` OR a `guest_id` populated, but rarely both, depending on whether the reactor is a logged-in user or an anonymous visitor.
- **Soft Deletes:** Odoo staging tables often contain the full history; check for existence of `active` or `deleted` flags in the source system if filtering for current state is required.
- **Type Precision:** The `content` column is defined as `VARCHAR` without length; assume standard emoji/text length but verify against source DDL if performing bulk loads into fixed-width targets.
