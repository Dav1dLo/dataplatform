# odoo_product_template

## Source system
This table originates from Odoo ERP, specifically the `product.template` model. The naming conventions (e.g., `categ_id`, `uom_id`, `create_uid`, `write_uid`) and the heavy use of `JSONB` for multi-language fields and property configurations are characteristic of the Odoo ORM architecture.

## Functional process 
This table supports the Product Lifecycle Management and Catalog Management processes. It acts as the central repository for product definitions, including pricing, procurement rules, sales policies, and inventory configuration, serving as the master data source for downstream sales, purchasing, and inventory modules.

## Description
One row in this table represents a single product template, which defines the core attributes of a product before it is instantiated as specific variants. It serves as a raw landed copy of the Odoo `product.template` table, capturing the configuration state of the product catalog at the time of ingestion.

## Caveats for downstream consumers

- **Sensitive Data:** Contains `JSONB` fields that may store internal notes or descriptions; ensure these are reviewed for PII if exposed to external reporting.
- **Timestamps:** `create_date` and `write_date` are stored in UTC as per Odoo standard behavior.
- **Soft Deletes:** The `active` column acts as a soft-delete flag. Always filter by `WHERE active = TRUE` unless you specifically need to analyze archived/historical products.
- **JSONB Complexity:** Many fields (e.g., `name`, `description`, `property_*`) are `JSONB`. These require extraction (e.g., `name->>'en_US'`) to be used in standard SQL reporting.
- **Data Precision:** `NUMERIC` types are used for financial and physical measurements; ensure downstream systems handle the scale/precision appropriately to avoid rounding errors.
