# odoo_account_move

## Source system
This table originates from Odoo ERP, specifically the accounting and invoicing module. The naming conventions (e.g., `journal_id`, `move_type`, `invoice_date_due`) and the presence of Odoo-specific fields like `inalterable_hash` and `auto_post` are characteristic of the Odoo `account.move` model, which serves as the central ledger for all accounting entries.

## Functional process 
This table supports the core financial accounting and billing process, including the generation of invoices, credit notes, and manual journal entries. It tracks the lifecycle of a financial transaction from creation through posting (`state`), payment reconciliation (`payment_state`), and reporting, acting as the primary source for financial statements and accounts receivable/payable aging.

## Description
One row in this table represents a single accounting move (a journal entry), which may be an invoice, a vendor bill, or a general ledger adjustment. The grain is one entry per move ID. In the staging layer, this table provides a raw, denormalized snapshot of the Odoo `account.move` table, capturing both header-level financial data and metadata for downstream transformation into financial fact tables.

## Caveats for downstream consumers

- **Sensitive Data:** Contains `invoice_source_email` and `invoice_partner_display_name`, which are PII.
- **Timestamps:** `create_date` and `write_date` are stored in UTC.
- **Soft Deletes:** Odoo typically does not use soft deletes for `account.move`; cancelled entries remain in the table with a `state` of 'cancel'.
- **Financial Precision:** `NUMERIC` fields are generally accurate to 2 decimal places, but check Odoo configuration for multi-currency rounding settings.
- **Signed Amounts:** `_signed` columns are critical for financial reporting as they correctly handle the debit/credit nature of the entry (e.g., credit notes will have negative values).
