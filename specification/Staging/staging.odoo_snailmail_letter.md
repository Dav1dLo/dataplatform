# odoo_snailmail_letter

## Source system
This table originates from Odoo ERP, specifically the `snailmail` module which handles the physical mailing of documents. The naming convention (e.g., `res_id`, `partner_id`, `create_uid`) and the specific module-related fields like `report_template` and `attachment_id` are characteristic of Odoo's internal ORM structure.

## Functional process 
This table supports the physical document delivery process (Snailmail). It tracks the lifecycle of letters generated from Odoo records, managing the association between digital documents (attachments), the target recipients (partners), and the physical mailing status (state, error codes, and address details).

## Description
One row represents a single physical letter request initiated within the Odoo system. This table acts as a raw landing copy of the `snailmail.letter` model, capturing the metadata, delivery status, and destination address for each mailing event.

## Caveats for downstream consumers

- **PII:** Contains physical address information (`street`, `street2`, `zip`, `city`) which is considered PII.
- **Timestamps:** Assumed to be in UTC, consistent with standard Odoo database configurations.
- **Soft Deletes:** Odoo typically does not use soft deletes; records are usually hard-deleted unless an `active` column (not present here) is used.
- **Data Integrity:** The `model` column is a string identifier; ensure joins involving `res_id` are scoped by the `model` value to avoid collisions across different Odoo tables.
