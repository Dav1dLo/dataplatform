# odoo_res_partner

## Source system
This table originates from Odoo ERP, specifically the `res.partner` model. The naming conventions (`res_partner`, `create_uid`, `write_date`, `property_*` fields) and the specific Odoo-centric data types like `JSONB` for property fields and `peppol_*` identifiers are characteristic of the Odoo framework's core contact management module.

## Functional process 
This table supports the "Partner Management" business process, which acts as the central repository for all entities Odoo interacts with, including customers, suppliers, and internal company contacts. It manages the lifecycle of business relationships, including contact details, financial settings (credit limits, payment terms), and logistics configurations (stock locations, purchase/sale warnings).

## Description
One row in this table represents a single partner entity, which can be an individual or a company. It serves as a raw landed copy of the Odoo `res.partner` table, capturing the full state of contact information, financial properties, and operational flags. The grain is one row per unique partner ID.

## Caveats for downstream consumers

- **Sensitive Data:** Contains PII including `email`, `phone`, `mobile`, `street`, and `vat`. Masking is recommended for non-authorized users.
- **Timestamps:** All `TIMESTAMP` fields are stored in UTC by Odoo.
- **Soft Deletes:** The `active` column is a standard Odoo soft-delete flag. Queries should generally filter by `WHERE active = TRUE` unless historical/archived data is required.
- **JSONB Fields:** Many financial and configuration settings are stored in `JSONB` columns. These require specific PostgreSQL operators (e.g., `->>`, `::jsonb`) to extract values for analysis.
- **Data Quality:** `email_normalized` and `phone_sanitized` are preferred for joining or deduplication over the raw `email` and `phone` fields.
