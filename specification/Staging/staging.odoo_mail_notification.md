# odoo_mail_notification

## Source system
This table originates from Odoo, an open-source ERP system. The naming convention (e.g., `res_partner_id`, `mail_message_id`, `mail_mail_id`) and the specific structure of notification tracking are characteristic of the Odoo `mail` module, which manages internal and external communications.

## Functional process 
This table supports the communication and notification tracking process within Odoo. It records the delivery status of messages sent to partners (customers, employees, or vendors), tracking whether messages were read, successfully delivered, or failed, and providing diagnostic information for SMS or physical letter delivery attempts.

## Description
One row represents a single notification event for a specific message recipient, tracking the delivery status and interaction state (read/unread). This table acts as a raw landing copy of the Odoo `mail_notification` model, capturing the state of communications at the time of ingestion.

## Caveats for downstream consumers

- **Sensitive Data:** `sms_number` contains PII (phone numbers) and should be masked or restricted according to data privacy policies.
- **Timestamps:** `read_date` is stored in the Odoo application's timezone; verify if this matches your warehouse UTC standard.
- **Data Integrity:** This is a raw staging table; it may contain multiple records for the same `mail_message_id` depending on the number of recipients.
- **Soft Deletes:** Odoo typically does not use soft-delete flags in this table; records are generally immutable once created, though status updates may occur.
