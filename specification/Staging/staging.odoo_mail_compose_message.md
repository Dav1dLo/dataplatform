# odoo_mail_compose_message

## Source system
This table originates from Odoo ERP, specifically the mail module. The naming convention (`mail_compose_message`) and the presence of Odoo-specific fields like `res_domain`, `model`, and `email_layout_xmlid` are characteristic of the Odoo framework's internal messaging and notification system.

## Functional process 
This table supports the communication and notification pipeline within Odoo. It acts as a transient or staging area for composing emails, internal notes, or system notifications before they are dispatched or linked to specific business records (e.g., sales orders, invoices, or CRM leads) defined by the `model` and `res_ids` columns.

## Description
One row in this table represents a single message composition event, capturing the metadata, content, and configuration for an outgoing email or internal notification. It serves as a raw landing copy of the Odoo `mail.compose.message` model, capturing the state of a message at the time of ingestion into the staging layer.

## Caveats for downstream consumers

- **PII:** The `body`, `email_from`, and `subject` columns may contain PII. Ensure appropriate masking if exposing to non-authorized users.
- **Timestamps:** `create_date` and `write_date` are assumed to be in UTC, consistent with Odoo's internal storage.
- **Data Grain:** This table captures the composition state; it does not necessarily represent successfully sent emails.
- **Text Fields:** `res_ids` and `res_domain` are stored as text and may require parsing (e.g., JSON or Python literal evaluation) to be useful for joins.
