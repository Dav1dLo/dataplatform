# odoo_project_project

## Source system
This table originates from Odoo ERP, specifically the Project Management module. The naming convention `odoo_project_project` and the presence of Odoo-specific fields like `create_uid`, `write_uid`, and `alias_id` are characteristic of Odoo's PostgreSQL database schema.

## Functional process 
This table supports the project management and service delivery lifecycle. It tracks project definitions, visibility settings, and configuration for task dependencies and billing, acting as the central entity for project-based work tracking within the Odoo ecosystem.

## Description
One row represents a single project entity within the Odoo system, capturing its configuration, timeline, and administrative metadata. This table serves as a raw landed staging entity, preserving the source system's structure including JSONB fields for localized names and task labels.

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):**
    - `partner_id` → `res_partner.id` (Standard Odoo link to customer/vendor)
    - `company_id` → `res_company.id` (Standard Odoo multi-company link)
    - `user_id` → `res_users.id` (Standard Odoo link to system users)
- **Natural keys (inferred):**
    - None. Odoo projects are typically identified by their surrogate `id` within the database.

## Caveats for downstream consumers

- **Sensitive Data:** The `access_token` and `description` fields may contain sensitive information or internal notes; ensure appropriate masking if exposing to non-admin users.
- **Timestamps:** All `TIMESTAMP` fields are assumed to be in UTC, consistent with standard Odoo database configurations.
- **Soft Deletes:** The `active` boolean column acts as a soft-delete flag. Queries should generally filter by `WHERE active = TRUE` unless historical/archived data is required.
- **JSONB:** The `name`, `label_tasks`, and `task_properties_definition` columns contain JSONB data. Use PostgreSQL `->>` or `->` operators to extract values for reporting.
