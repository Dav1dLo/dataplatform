# odoo_ir_model_access

## Source system
This table originates from Odoo ERP. The naming convention `ir_model_access` is a standard internal table name within the Odoo "Ir" (Irrelevant/Internal) module, which manages the system's security and access control layer.

## Functional process 
This table supports the Odoo security and authorization framework. It defines the Access Control Lists (ACLs) that determine which user groups have permission to read, write, create, or delete records for specific data models within the ERP.

## Description
One row in this table represents a single access rule assigned to a specific security group for a given Odoo model. This is a raw landing of the Odoo `ir.model.access` table, serving as the staging layer source for auditing system permissions and user access rights.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Sequence-generated by Odoo. |
| model_id | INTEGER | false | Foreign key to the model | References the `ir_model` table. |
| group_id | INTEGER | true | Foreign key to the security group | References the `res_groups` table; null implies global access. |
| create_uid | INTEGER | true | Creator user ID | References the `res_users` table. |
| write_uid | INTEGER | true | Last modifier user ID | References the `res_users` table. |
| name | VARCHAR | false | Rule description | Human-readable name for the access rule. |
| active | BOOLEAN | true | Soft-delete flag | Indicates if the access rule is currently enabled. |
| perm_read | BOOLEAN | true | Read permission | True if the group can view records. |
| perm_write | BOOLEAN | true | Write permission | True if the group can edit records. |
| perm_create | BOOLEAN | true | Create permission | True if the group can create new records. |
| perm_unlink | BOOLEAN | true | Delete permission | True if the group can delete records. |
| create_date | TIMESTAMP | true | Creation timestamp | Recorded in UTC by the Odoo server. |
| write_date | TIMESTAMP | true | Last update timestamp | Recorded in UTC by the Odoo server. |

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `model_id` → `staging.odoo_ir_model.id`: Links the access rule to the specific data model being restricted.
    - `group_id` → `staging.odoo_res_groups.id`: Links the rule to the specific security group (if applicable).
    - `create_uid` → `staging.odoo_res_users.id`: Links to the user who created the rule.
    - `write_uid` → `staging.odoo_res_users.id`: Links to the user who last modified the rule.
- **Natural keys (inferred):** Not confidently inferable from the provided metadata.

## Caveats for downstream consumers

- **Timestamps:** All `create_date` and `write_date` values are stored in UTC.
- **Soft Deletes:** The `active` column acts as a soft-delete flag; queries should generally filter by `WHERE active = TRUE` unless performing an audit of historical/disabled rules.
- **Global Access:** If `group_id` is NULL, the rule typically applies to all users (global access), which is a critical distinction for security reporting.
- **Data Sensitivity:** This table contains metadata about system security configurations; while it does not contain PII, it defines the boundaries of data access across the entire ERP.
