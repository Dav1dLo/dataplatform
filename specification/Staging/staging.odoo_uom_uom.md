# odoo_uom_uom

## Source system
This table originates from Odoo ERP, as evidenced by the naming convention (`odoo_uom_uom`), the presence of standard Odoo audit columns (`create_uid`, `write_uid`, `create_date`, `write_date`), and the use of `JSONB` for multi-language name fields.

## Functional process 
This table supports the inventory and product management modules by defining Units of Measure (UoM). It manages the conversion factors and rounding precision required for stock movements, procurement, and sales order line calculations.

## Description
One row in this table represents a single unit of measure definition (e.g., "kg", "dozen", "piece") within the Odoo system. It serves as a raw landed copy of the Odoo `uom.uom` model, providing the base configuration for how quantities are measured and converted across the platform.

## Caveats for downstream consumers

- **Timestamps:** All `create_date` and `write_date` values are stored in UTC.
- **Soft Deletes:** The `active` column acts as a soft-delete flag; queries should generally filter by `WHERE active = TRUE` unless performing historical audits.
- **JSONB:** The `name` column contains JSON data; use `name->>'en_US'` or similar syntax to extract specific language strings.
- **Precision:** `factor` and `rounding` are `NUMERIC` types; ensure downstream systems handle these as high-precision decimals to avoid floating-point errors in inventory calculations.
