# odoo_sms_sms

## Source system
This table originates from Odoo ERP, specifically the SMS marketing or communication module. The naming convention `odoo_sms_sms` and the presence of Odoo-specific audit columns like `create_uid` and `write_uid` are characteristic of Odoo's internal PostgreSQL schema.

## Functional process 
This table supports the SMS communication and notification pipeline. It tracks the lifecycle of individual SMS messages sent through the platform, including their delivery status, associated recipient partners, and the content of the messages, facilitating audit trails for customer engagement and marketing campaigns.

## Description
One row in this table represents a single SMS message record, capturing its delivery state, recipient, and content. As a staging table, it serves as a raw, direct reflection of the Odoo `sms_sms` database table, intended for use in downstream transformations to build communication analytics or delivery performance reports.

## Caveats for downstream consumers

- **Sensitive Data:** The `number` (phone number) and `body` (message content) columns contain PII and should be masked or restricted based on data privacy policies.
- **Timezone:** Timestamps (`create_date`, `write_date`) are stored in the Odoo server's timezone, typically UTC, but should be verified against the source system configuration.
- **Soft Deletes:** The `to_delete` column suggests a soft-delete pattern; ensure queries filter for `to_delete = FALSE` or `IS NULL` to exclude records intended for removal.
- **State Logic:** The `state` column is a string-based status; downstream models should map these values to a consistent set of statuses (e.g., 'sent', 'failed', 'pending').
