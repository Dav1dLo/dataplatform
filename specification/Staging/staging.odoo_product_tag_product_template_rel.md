# odoo_product_tag_product_template_rel

## Source system
Odoo ERP. The naming convention `_rel` combined with the specific entity names `product_template` and `product_tag` is characteristic of Odoo's internal many-to-many relationship tables, which are automatically generated by the Odoo ORM to link product templates to their associated tags.

## Functional process 
Product catalog management and classification. This table supports the categorization of products within the Odoo inventory or e-commerce module, allowing a single product template to be associated with multiple tags (e.g., "New Arrival", "Clearance", "Eco-friendly") and vice versa.

## Description
One row represents a single association between a product template and a product tag. This is a junction table used to resolve a many-to-many relationship between the `product_template` and `product_tag` entities. It serves as a raw landed copy of the Odoo database link table, intended for use in joining product metadata with classification attributes.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| product_template_id | INTEGER | false | Foreign key to the product template | Links to the primary product definition. |
| product_tag_id | INTEGER | false | Foreign key to the product tag | Links to the specific tag definition. |

## Keys

- **Primary key (inferred):** The combination of `(product_template_id, product_tag_id)`.
- **Foreign keys (inferred):** 
    - `product_template_id` → `product_template.id`: This column references the primary identifier of the product template entity.
    - `product_tag_id` → `product_tag.id`: This column references the primary identifier of the product tag entity.
- **Natural keys (inferred):** Not confidently inferable from the provided metadata.

## Caveats for downstream consumers

- This table contains no surrogate primary key; queries should use the composite key `(product_template_id, product_tag_id)` for joins or deduplication.
- There are no timestamps or audit columns present; it is impossible to determine the history of when these associations were created or modified from this table alone.
- This is a pure junction table; it contains no descriptive attributes, only identifiers.
- Ensure that downstream joins handle the potential for multiple rows per `product_template_id` if a product has multiple tags assigned.
