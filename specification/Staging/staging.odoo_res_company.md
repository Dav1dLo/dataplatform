# odoo_res_company

## Source system
This table originates from Odoo ERP, specifically the `res.company` model. The naming conventions (e.g., `res_company`, `partner_id`, `currency_id`) and the extensive configuration columns related to accounting, HR, and inventory are characteristic of the Odoo core framework.

## Functional process 
This table supports the multi-company configuration and management process within Odoo. It acts as the central registry for organizational entities, defining their legal identity, accounting settings (fiscal years, tax configurations, chart of accounts), and operational parameters for modules like Sales, Inventory, and HR.

## Description
One row in this table represents a single company or legal entity defined within the Odoo instance. It serves as a master configuration record, storing both static metadata (name, contact details) and complex operational settings (accounting lock dates, manufacturing lead times, and portal configurations). This is a raw landed copy of the Odoo `res_company` model, intended for use in downstream staging and transformation pipelines.

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `partner_id` → `res_partner.id` (Standard Odoo link between company and partner record).
    - `currency_id` → `res_currency.id` (Defines the base currency for the company).
    - `parent_id` → `res_company.id` (Self-reference for hierarchical company structures).
- **Natural keys (inferred):** 
    - `name` (While not strictly unique in all Odoo configurations, it is the primary business identifier for a company).

## Caveats for downstream consumers

- **Sensitive Data:** The `logo_web` column contains binary image data. `email`, `phone`, and `mobile` are PII.
- **Timestamps:** `create_date` and `write_date` are stored in UTC.
- **Soft Deletes:** The `active` column acts as a soft-delete flag. Queries should generally filter by `WHERE active = TRUE` unless historical analysis of inactive companies is required.
- **JSONB:** Several columns (`report_header`, `report_footer`, `company_details`, `invoice_terms`, `employee_properties_definition`) use `JSONB`. Use PostgreSQL JSONB operators (e.g., `->>`) to extract values.
- **Precision:** `manufacturing_lead`, `po_lead`, and `security_lead` are `DOUBLE PRECISION` representing days. `po_double_validation_amount` is `NUMERIC` and should be treated as a currency value.
