# odoo_stock_picking

## Source system
This table originates from Odoo ERP, specifically the Inventory/Warehouse management module. The naming convention (`stock_picking`, `picking_type_id`, `location_dest_id`) and the presence of Odoo-specific audit columns (`create_uid`, `write_uid`) are characteristic of the Odoo PostgreSQL schema.

## Functional process 
This table supports the warehouse logistics and fulfillment process, tracking the movement of goods between locations. It acts as the central header for stock operations, linking sales orders (`sale_id`), point-of-sale sessions (`pos_session_id`), and internal inventory transfers to specific warehouse locations and responsible users.

## Description
One row represents a single stock picking operation (a header record for a warehouse movement). It captures the status, scheduling, and source/destination context of an inventory transfer. As a staging table, it provides a raw, landed copy of the Odoo `stock_picking` model, intended for downstream transformation into inventory fact tables.

## Caveats for downstream consumers

- **Timestamps:** All timestamps are stored in UTC as per standard Odoo configuration.
- **Soft Deletes:** Odoo typically does not use soft deletes; records are generally permanent, though `state` should be used to filter out cancelled operations.
- **Sensitive Data:** `partner_id` links to PII in the `res_partner` table; ensure appropriate access controls are applied when joining.
- **JSONB:** The `picking_properties` column contains unstructured data; parsing this requires `jsonb` extraction functions which may impact query performance on large datasets.
