# odoo_stock_scrap

## Source system
This table originates from Odoo ERP, specifically the Inventory/Warehouse management module. The naming convention (`stock_scrap`, `picking_id`, `product_uom_id`) and the presence of Odoo-specific audit columns (`create_uid`, `write_uid`, `create_date`) are characteristic of the Odoo PostgreSQL schema.

## Functional process 
This table supports the inventory adjustment and waste management process. It tracks items removed from inventory due to damage, expiration, or other loss, linking these scrap events to specific products, source locations, and potentially manufacturing orders (`production_id`, `workorder_id`, `bom_id`).

## Description
One row represents a single scrap event where a specific quantity of a product is removed from a designated inventory location. This is a raw landed copy of the Odoo `stock.scrap` model, capturing the state of inventory write-offs at the grain of an individual scrap transaction.

## Caveats for downstream consumers

- **Timestamps:** All `_date` columns are stored in UTC by Odoo.
- **Soft Deletes:** Odoo typically does not use soft deletes; records are generally permanent unless purged by system maintenance.
- **Precision:** `scrap_qty` is `NUMERIC` to support fractional quantities; ensure downstream systems handle decimal precision appropriately.
- **Sensitive Data:** No direct PII is present, though `create_uid` and `write_uid` link to user records which may contain personal information.
