# odoo_ir_logging

## Source system
This table originates from Odoo ERP, specifically the `ir_logging` model within the Odoo framework. The naming convention (`ir_` prefix for "internal resource") and the presence of standard Odoo audit columns (`create_uid`, `write_uid`, `create_date`, `write_date`) are characteristic of Odoo's internal logging and system tracking infrastructure.

## Functional process 
This table supports system monitoring and audit logging within the Odoo application. It captures runtime events, errors, and diagnostic messages generated by the application server, which are used for debugging, performance monitoring, and security auditing of system operations.

## Description
One row in this table represents a single log entry generated by the Odoo application server. It records the context of the event, including the function, file path, line number, and the associated log message. This is a raw landed copy of the Odoo system logs, serving as the primary source for observability and audit reporting in the staging layer.

## Caveats for downstream consumers

- **Sensitive Data:** The `message` column may contain PII or system configuration details depending on the log level; ensure masking if exposing to non-admin users.
- **Timezone:** Timestamps are assumed to be in UTC, consistent with Odoo's internal storage practices.
- **Data Retention:** This table is likely append-only; expect high volume and consider partitioning by `create_date` for performance.
- **Type Casting:** The `line` column is stored as `VARCHAR` despite representing a numeric line number; cast to `INTEGER` for sorting or filtering.
- **Soft Deletes:** Odoo typically does not use soft deletes for `ir_logging` records; assume rows are permanent unless purged by system maintenance.
