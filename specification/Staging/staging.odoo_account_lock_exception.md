# odoo_account_lock_exception

## Source system
This table originates from Odoo ERP, as indicated by the naming convention (`odoo_` prefix, `_uid` suffix for user references, and `create_date`/`write_date` audit columns). It specifically tracks administrative overrides for accounting period locks.

## Functional process 
This table supports the financial compliance and audit process by logging exceptions to standard accounting lock dates. It allows specific users or companies to bypass system-enforced date restrictions for posting entries, typically used during month-end or year-end closing adjustments.

## Description
One row represents a single authorized exception to an accounting lock date, defining the scope (company), the duration of the override, and the justification. This is a raw landing table in the Staging layer, capturing the state of the Odoo `account.lock.exception` model.

## Caveats for downstream consumers

- **Sensitive Data:** Contains user IDs and business reasons for financial overrides; ensure access is restricted to authorized financial auditors.
- **Timestamps:** All `TIMESTAMP` fields are assumed to be in UTC, consistent with Odoo's internal storage.
- **Soft Deletes:** The `active` column acts as a soft-delete flag; queries should generally filter by `WHERE active = TRUE` unless performing an audit of historical exceptions.
- **Precision:** `VARCHAR` fields do not have explicit lengths defined in the metadata; downstream consumers should handle potential variable-length strings gracefully.
