# odoo_hr_work_location

## Source system
This table originates from Odoo ERP, specifically the Human Resources module. The naming convention (`hr_work_location`) and the presence of Odoo-standard audit columns (`create_uid`, `write_uid`, `create_date`, `write_date`) are characteristic of Odoo's PostgreSQL schema.

## Functional process 
This table supports the management of physical work locations for employees within the organization. It is used to define where staff are stationed, which is critical for payroll, tax jurisdiction reporting, and office space allocation within the HR-to-Payroll pipeline.

## Description
Each row represents a specific physical work location defined within the Odoo HR module. This is a raw landed staging table containing the current configuration of work sites, including their association with company entities and address records.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Sequence-generated by Odoo. |
| company_id | INTEGER | false | Foreign key to company | Links the location to a specific legal entity. |
| address_id | INTEGER | false | Foreign key to address | Links to the partner/address record for location details. |
| create_uid | INTEGER | true | Creator user ID | ID of the user who created the record. |
| write_uid | INTEGER | true | Last modifier user ID | ID of the user who last updated the record. |
| name | VARCHAR | false | Location name | Human-readable name of the work site. |
| location_type | VARCHAR | false | Type of location | Categorization of the site (e.g., office, remote, warehouse). |
| location_number | VARCHAR | true | Location identifier | Internal code or number assigned to the site. |
| active | BOOLEAN | true | Soft-delete flag | If false, the location is archived/inactive. |
| create_date | TIMESTAMP | true | Creation timestamp | UTC timestamp of record creation. |
| write_date | TIMESTAMP | true | Last update timestamp | UTC timestamp of last modification. |

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `company_id` → `res_company.id` (Standard Odoo multi-company architecture).
    - `address_id` → `res_partner.id` (Standard Odoo pattern for linking locations to address books).
- **Natural keys (inferred):** 
    - `name` (within the context of a `company_id`).

## Caveats for downstream consumers

- **Soft Deletes:** The `active` column acts as a soft-delete flag. Queries should generally filter by `WHERE active = true` unless historical audit is required.
- **Timestamps:** Timestamps are stored in UTC as per standard Odoo configuration.
- **PII:** While this table contains location metadata, ensure that any joined `address_id` records are handled according to data privacy policies, as they may contain sensitive contact information.
- **Data Integrity:** As a staging table, this is a direct reflection of the source; expect potential inconsistencies in `location_type` values if they are free-text fields in the source UI.
