# odoo_discuss_channel_member

## Source system
This table originates from Odoo ERP, specifically the Discuss module. The naming convention (`discuss_channel_member`, `partner_id`, `guest_id`) and the presence of Odoo-standard audit columns (`create_uid`, `write_uid`, `create_date`, `write_date`) are characteristic of the Odoo framework's internal data structure.

## Functional process 
This table supports the internal messaging and collaboration infrastructure within Odoo. It tracks the membership status of users (partners) or guests within specific communication channels, managing state such as message read-tracking, notification preferences, and UI display settings like channel folding.

## Description
One row in this table represents a single membership association between a specific user/guest and a communication channel. It acts as a raw landing copy of the Odoo `mail.channel.member` model, capturing the grain of one member per channel per session. Its purpose in the staging layer is to provide a granular record of user interaction states within the messaging system for downstream reporting on engagement or notification settings.

## Caveats for downstream consumers

- **Sensitive Data:** Contains `partner_id` and potentially identifiable `custom_channel_name` values; ensure PII compliance if exposing to non-admin users.
- **Timestamps:** All `_dt` and `_date` columns are assumed to be in UTC, consistent with standard Odoo server-side storage.
- **Soft Deletes:** This table does not appear to use a `deleted` flag; records are likely hard-deleted by the Odoo ORM when a member leaves a channel.
- **Data Quality:** `partner_id` and `guest_id` are mutually exclusive in many contexts; ensure queries handle the logic where a member is either a registered partner or a guest.
