# odoo_crm_lost_reason

## Source system
This table originates from Odoo ERP, specifically the CRM module. The naming convention (`crm_lost_reason`), the presence of audit fields (`create_uid`, `write_uid`, `create_date`, `write_date`), and the use of `JSONB` for the `name` field are characteristic of Odoo's internal data structure for managing configuration entities.

## Functional process 
This table supports the sales pipeline management process by defining the categorical reasons why a sales opportunity (lead/opportunity) was marked as "lost". These reasons are used by sales teams to track churn signals and improve conversion strategies.

## Description
One row represents a single, configurable reason code used to classify lost sales opportunities within the CRM. This is a raw landing table in the Staging layer, capturing the state of the Odoo `crm.lost.reason` model as it exists in the source database.

## Columns

| Column | Type | Nullable | Meaning | Notes |
| :--- | :--- | :--- | :--- | :--- |
| id | INTEGER | false | Surrogate primary key | Sequence-generated by Odoo. |
| create_uid | INTEGER | true | User ID who created the record | References `res.users`. |
| write_uid | INTEGER | true | User ID who last updated the record | References `res.users`. |
| name | JSONB | false | The display name of the lost reason | Odoo stores multi-language strings here; expect keys like 'en_US'. |
| active | BOOLEAN | true | Soft-delete flag | If false, the reason is hidden from the CRM UI. |
| create_date | TIMESTAMP | true | Record creation timestamp | Inferred UTC based on Odoo standard. |
| write_date | TIMESTAMP | true | Last update timestamp | Inferred UTC based on Odoo standard. |

## Keys

- **Primary key (inferred):** `id`
- **Foreign keys (inferred):** 
    - `create_uid` → `res_users.id`: Tracks the creator of the configuration record.
    - `write_uid` → `res_users.id`: Tracks the last user to modify the record.
- **Natural keys (inferred):** 
    - `name`: While stored as JSONB, the business logic typically enforces uniqueness on the translated name values.

## Caveats for downstream consumers

- **JSONB Handling:** The `name` column contains localized strings. Query writers must extract the relevant language key (e.g., `name->>'en_US'`) to use this field in reports.
- **Soft Deletes:** The `active` column acts as a soft-delete flag. Ensure queries filter by `active = TRUE` unless historical/archived reasons are explicitly required.
- **Timezone:** Timestamps are stored in the Odoo application server time, which is typically UTC.
- **Audit Fields:** `create_uid` and `write_uid` refer to internal Odoo user IDs; these will not resolve to meaningful names without joining to the `res_users` staging table.
